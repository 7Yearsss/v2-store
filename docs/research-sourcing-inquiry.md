# 询货（sourcing inquiry）调研

> 2026-09-24。"询货"在我们产品里对应模块 = **货源匹配/询价**：拿到下游商品（或采集来的商品），在货源侧找到可代发的供应商并评估。

## 三层"询货"语义

1. **找货源（最核心）**：下游平台商品（图/链接/标题）→ 1688 以图搜款 + 关键词搜 → 候选供应商列表。芝麦 `platformInquiry` / `startAiInquiry` 干的就是这个：Ozon 商品卡 → 1688 同款 → 比价判可行性
2. **询盘/寻源（RFQ）**：模糊采购需求（名称+数量+要求）→ 发布询盘让供应商报价——1688 官方有这个撮合能力，但我们场景更多是定向问单品
3. **售前询盘（问卖家）**：对已选定 offer 向供应商发问题（"支持一件代发吗""能贴牌吗""走什么物流"），读取回复——工具化后是 `inquire(offerId, question)` + 消息监听

## 评估供应商的信号（询货输出要带的字段）

| 信号 | 来源 |
|---|---|
| channelPrice 一件代发包邮价 | `alibaba.cpsMedia.productInfo` / 页面 priceRange |
| 阶梯价 + MOQ | `alibaba.product.get` / 页面 skuModel |
| 代发保障：48h 发货、7 天包退 | 页面服务保障标签 |
| 供应商资质：诚信通年限、工厂档案、回头率 | 供应商详情 / `alibaba.wholesale.supplier.get` |
| 同款多货源比价 | 以图搜款返回列表排序 |

## 在产品里的位置

```
目标平台商品（或被采集品）
   → 询货 job：以图搜款/关键词搜 1688 → 候选排序（价/库存/代发/资质打分）
   → 选定供应商 → AI 管线 → ChannelAdapter 刊登
   → 出单后按绑定的供应商走采购（订单回流）
```

即"询货"是**采集的反向**：采集是 1688→下游，询货是 下游→1688（选品 sourcing）。两个方向共享同一套 OfferSource/解析器。

## 实现注意

- 以图搜款：1688 `item_search_img`（官方 API）或页面层以图搜入口上传图片——插件可代理页面侧调用（用户 session）
- 售前询盘自动化要谨慎：自动发消息给供应商频率过高会触发账号风控，建议做成"待发送队列 + 人工确认"
- 评分维度先做简单规则（代发价最低 + 有代发保障 + 回头率），别上来就 ML
