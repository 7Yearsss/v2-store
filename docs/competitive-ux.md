# 竞品 Web 端操作逻辑与我们的差异化定位

调研对象：店小秘（帮助中心公开文档）、芒果店长（帮助中心）、AutoDS（help center）、**妙手 ERP（登录后台实测 + 插件拆解）**。
注：妙手部分为 2026-09 登录 erp.91miaoshou.com 的实测观察。

## 一、行业收敛出的标准操作模型

三家产品形态不同，但核心链路完全一致：

```
采集(多种入口) → 通用采集箱 → 认领到目标店铺 → 平台草稿箱
  → 编辑(类目/变种/定价/物流/AI优化) → 发布 → 在线商品 + 库存价格监控 → 订单回流
```

关键设计点：

### 1. 两级缓冲：通用采集箱 → 平台草稿箱
- **店小秘**：采集统一进「通用采集箱」（未认领保留半年），「认领」到具体平台店铺后进入该平台的采集箱（永久保留）。认领 = 把货源数据绑定到一个目标店铺的动作。
- **芒果店长**：采集成功先进「采集中心/采集箱」，认领后出现在【产品 → 产品刊登 → 具体平台】的草稿箱，在那里编辑发布。
- **AutoDS**：import 时可选择直接进 Drafts；Drafts 页承担"发布前审查"，发完后进 Products 页。

> 对我们：product 表的 `status: draft → processed → listed` 就是这个两级模型的简化版；`targetChannel` 字段承担"认领到店铺"的角色。**认领动作是不可省的**——它是把"采集来的别人的数据"转化成"我的待刊登草稿"的确认点。

### 2. 采集入口矩阵（店小秘的六种）

| 采集方式 | 说明 | 我们的对应 |
| --- | --- | --- |
| 链接采集 | 粘贴商品 URL 采到采集箱 | web 端贴链接 → extension/site-bridge 或后台采 |
| 分类采集 | 整批采店铺某分类 | 整店采集的变体 |
| 关键词采集 | 关键词+价格区间搜 1688 批量采 | 搜索页采集（本期已做） |
| 插件采集 | 详情页按钮 | 已有 |
| 整店采集 | 店铺全部商品 | 已有（嗅探+按ID批量拉） |
| 导入采集 | Excel/链接批量导入 | 后续：CSV 导入 |

店小秘的运营细节值得抄：同平台采集认领要 VIP（防速卖通→速卖通纯搬运）、子账号可限制"只能看自己采的"、淘宝风控严格官方建议别采——**他们主动用规则把灰色用法变贵、把合规用法做顺**。

### 3. 编辑页是平台定制的，不是通用表单
芒果的批量编辑页字段按平台展开：类目（平台 taxonomy 选择器）、父 SKU、标题（带平台 SEO 提示）、描述、标签（"超过10个被系统忽略"的平台规则提示）、运费（含平台佣金提醒）、UPC/GTIN（提醒"国内产品没有需购买"）。每个字段都是一条平台规则的产品化。

> 对我们：`ChannelAdapter.draft` 渲染的编辑器必须由平台 schema 驱动，而不是一张固定表单。MVP 可以先做通用编辑 + Shopify 字段，但架构上编辑表单 = 平台 schema × 产品数据。

### 4. AI 在大厂流程里是"可选加速步骤"，不是主链路
- 芒果「GPT一键发布」：1688 详情页插件按钮 → 自动采集 → 跳转发布页 → ChatGPT 生成标题/描述/价格/属性 → 直接发布（仅 Shopee，消耗"果粒"付费额度）。这是目前看到的**最激进**的 AI 集成——但仍是单点功能。
- 店小秘：AI 用在标题优化、违规词检测等环节，嵌在编辑页里。
- AutoDS：AI 写标题/描述是 drafts 编辑里的一个按钮。

### 5. 妙手实测：后台功能全景（2026-09，erp.91miaoshou.com）

顶栏十一个大域：产品 / 订单 / 托管 / 广告 / 数据 / 采购 / 仓库 / 物流 / 授权 + AI助理 + 插件下载。首页 = 待办聚合（产品待发布/发布中/失败，订单待处理/打单/交运失败，采购缺货建议/备货建议/待签收，托管备货单）+ 常用功能快捷入口 + 公告。

**链接采集页细节**：输入框支持 `链接$$新标题`、`产品ID||新标题` 等批量格式；源平台图标墙 20+（1688/淘宝/义乌小商品城/17货源/搜款网/网商园/货捕头/唯品会/衣联网等），再按类目 × 区域货盘（美区/加拿大/墨西哥/欧洲/东南亚/日韩/俄罗斯…）筛选；底部「自动认领(发布)到平台」勾选 + 采集并自动认领/采集并自动发布按钮——**采集→认领→发布可以三合一**。

**授权页实测**：42 个平台授权位（Shopee/Shopee全托管/Shopee轻出海、TikTok/TikTok全托管、Temu 全托管/半托管/本土、速卖通半托管/全托管/本土POP/海外托管、SHEIN半托管、Mercado 本土/全托、Ozon FBP/FBO、Shopify、SHOPYY、SHOPLINE…）。店铺表格字段：名称/所属全球店/站点/**类目等级**(L3→L7迁移提示)/分组/别名/状态/授权类型/授权时间。规则文案：多店铺授权不关联，一店只能授权给一个妙手账号。

**订单菜单实测**：订单处理/历史订单/直播打单/扫描分拣/扫描发货/售后管理/手工订单/利润明细/**货代管理**/采购记录；规则引擎（审单规则/分仓规则/物流匹配/赠品规则/自动标记/佣金规则）；组包预报（TikTok预报/Shopee首公里/Lazada组包/Temu提货单/Ozon发运单）；平台仓订单（各平台 FBS/FBM/FBA/WFS/FBO）；物流追踪/补录单号/黑名单/巴西发票/绩效。

**「托管」是一级菜单**——专门承接 Temu/美客多全托管/半托管模式的备货单、发货单、入库单流程，不是"代运营"。

**插件宣传点（下载弹窗原文）**：提高采集速度和成功率 / 获取更准确的货源信息 / 货源平台网页一键采集 / **自动监控货源平台信息变化**（=价格库存监控由插件侧做）。支持浏览器列表：Chrome/QQ/360极速/360安全/搜狗/紫鸟/站斧/飞跨——**指纹浏览器是跨境多店卖家的标配环境，插件必须兼容它们**。

## 二、差异化定位（我们的优势应该押在哪）

大厂赢在全（渠道多、订单仓储物流全家桶），输在重和老。我们不拼覆盖，拼下面几点：

**1. AI 是主链路，不是附加按钮**
大厂流程：采集 → 认领 → 进草稿箱 → （可选）点 AI 优化 → 发布。
我们：采集即入产线——**进采集箱时 AI 重写/翻译/合规过滤已自动跑完**，用户看到的是成品而不是原料。芒果的"GPT一键发布"证明了这条路转化率高，但他们只做了 Shopee 单点，我们把它做成默认管线。

**2. 询货（SourcingInquiry）反向链路**
下游商品 → 以图搜款找 1688 货源 → 比价评分 → 售前询盘。大厂都在"采集→刊登"正向链路上卷，反向的"有订单先找货源"几乎没人产品化（芝麦有 platformInquiry 雏形）。对无货源卖家这是真实高频场景。

**3. 插件与 web 一体化**
插件不只是采集按钮：web 端 ping 插件、触发采集、共享登录态（芝麦 bridge 模式已在我们骨架里）。大厂是"插件归插件、网页归网页"，我们可以让采集动作在工作台里原生发起。

**4. 窄平台切入 + 合规护栏**
不做全渠道 ERP：先只吃透 1688→Shopify 一条线（独立站无平台规则风险），同时把合规做成卖点——授权货源池优先、品牌词/侵权图自动过滤、敏感词拦截。店小秘用 VIP 门槛被动防滥用，我们可以主动把"不踩红线"做成 feature。

**5. 定价与上手成本**
大厂按店铺数/功能模块收费且功能臃肿；我们面向个人卖家和小团队做轻量订阅，核心路径三步走完。
