# V2Store 产品规划（给后续开发者 / AI 的主文档）

> 2026-09-25。基于：本仓库现状、妙手 ERP 后台实测（登录态，只读浏览）、AutoDS / DSers 帮助文档、既有调研（competitive-ux.md、teardown-*.md、research-*.md）。
> 读者：接手开发的人或 AI。先读本文，再读 `AGENTS.md`（仓库约定与已踩过的坑）。

---

## 1. 结论先行：我们赢在哪里，不赢在哪里

**不要高估“结合 AI”这张牌。** 实测妙手首页已经在推「妙手 Agent：你的专属 AI 运营团队」，后台有 AI 工作台（图片翻译 / 文生图 / 抠图 / 裂变 / 场景替换 / 高清放大 / 图生标题 / 一键发品 + 自定义工作流 + 积分计费）、AI 选品、AI 采集优化、AI 助理；AutoDS / DSers 的编辑页也都有 “Optimize with AI” 按钮。**“有 AI 功能”已经是行业标配，不是差异点。**

真正的差异点在 **AI 用在哪里、怎么用**：

| | 大厂现状（实测） | 我们要做的 |
|---|---|---|
| AI 的位置 | **独立工具页**：AI 工作台要自己“选择图片 → 设置参数 → 创建任务 → 去任务列表看结果”；侵权检测要手动上传图片；和采集→认领→刊登主流程是断开的 | **AI 在主流程里默认执行**：认领（或采集）即入 AI 产线，用户看到的是“待审核的成品”，而不是“原料 + 一堆工具” |
| 结果呈现 | 生成后直接覆盖或另存 | **可审核的差异（diff）**：原文 / AI 版并排，一键接受 / 回退 / 局部修改；批量接受 |
| 计费 | 积分，按次扣 | 套餐内含额度 + 超额按量；同样可用积分，但默认不打断主流程 |
| 合规 | 侵权检测是单独付费工具 | **发布前自动检查**（品牌词 / 敏感词 / 侵权图 / 平台规则），作为发布门禁的一环 |

**我们的第二个优势是交互现代化**，这点成立，但要落到具体的“少跳转、少等待、少猜测”上（见第 4 节），而不是换个 UI 皮肤。

**我们明确不赢的地方**：平台覆盖（妙手授权页 38 个平台 / 店小秘插件 384 个域名）、订单 / 仓库 / 物流 / 采购全链路、托管（全托管 / 半托管备货单）。**策略：窄切入、做深**。先把「1688 → Shopify 独立站」这一条线做到明显比他们好，再按同一套抽象扩到 1–2 个平台，不追全。

| 部署 | ❌ | 只在本地跑；无 CI |

## 3. 大厂踩过的坑 → 我们直接继承的设计

每条注明来源；“状态”列是本仓库是否已具备。

### 3.1 采集

| 设计 | 来源 | 为什么（他们踩过的坑） | 状态 |
|---|---|---|---|
| 采集箱 → 认领 → 平台草稿 两级缓冲 | 店小秘 / 芒果 / 妙手 | 采集的是“别人的数据”，认领是转成“我的待刊登商品”的确认点；未认领的数据要定期清理（店小秘半年、妙手失败数据 30 天） | ✅ |
| **采集时预处理**（「采集设置」「AI 采集优化」） | 妙手 | 用户不想对每个商品重复做同样的清洗：标题去供应商话术、加前后缀、敏感词替换、过滤价格区间、图片数量上限 | ❌ → Phase 1 |
| 「采集并自动认领 / 自动发布」三合一 | 妙手 | 熟练用户的主路径是“采了就上”，每多一步就流失 | ❌ → Phase 3（先保证 AI + 审核靠谱再开） |
| 批量链接格式 `链接$$新标题`、`ID\|\|新标题` | 妙手 | 运营从表格粘贴时顺带改标题 | ❌ 小功能 |
| 「采集失败」标签 + 「任务记录」 | 妙手 | 批量采集总有失败，用户需要知道哪些、为什么、能重试 | ❌ → Phase 3（任务中心） |
| 货源平台“授权”（1688 官方开放接口） | 妙手 | 纯插件抓页面会碰到风控 / 改版；官方接口稳定但字段少、要申请 | 调研项：作为插件之外的第二来源 |
| 页面改版的兜底 | 自身经历 | 1688 在 2025 年把 `__INIT_DATA` 换成 `window.context`（JS 对象字面量，非严格 JSON），旧解析全挂 | ✅ 解析在服务端可热更新 + 宽松 JSON |

### 3.2 采集箱 / 刊登列表

| 设计 | 来源 | 状态 |
|---|---|---|
| 筛选：货源 ID、标题、货源价格区间、平台 SKU、创建人、分组、关联货源 | 妙手采集箱 | 只有标题搜索 |
| **可保存的筛选视图**（Match All / Any） | AutoDS | ❌ |
| 列表列可配置（「列表设置」） | 妙手 / AutoDS | ❌ |
| 分组 / 标签 / 备注 / 创建人 | 妙手 / AutoDS | ❌（团队协作必需） |
| 草稿 / 定时 / 周期上架 三个标签 | AutoDS | ❌ |
| **状态要能解释**：On Hold（货源有货但不满足价格规则）、断货天数、失败原因可见 | AutoDS | 部分：发布失败原因 ✅，其余 ❌ |
| 货源信息变化提示（黄色感叹号：货源标题 / 价格变了） | AutoDS | ❌ → Phase 2 |
| 修改历史 | AutoDS | ❌ → Phase 5 |

### 3.3 编辑与发布

| 设计 | 来源 | 状态 |
|---|---|---|
| 编辑页按平台 schema 展开字段，每条平台规则做成提示（标签超 10 个被忽略、UPC 要买等） | 芒果 | ❌ Shopify 只做了基础校验 |
| 批量改价：“设为” / “在原值上调整”两种模式；变体级价格覆盖店铺规则 | AutoDS | ❌ |
| 发布前检查：侵权 / 商标 / 外观专利 | 妙手（独立付费工具） | ❌ → Phase 1 做成发布门禁 |
| 平台类目树会迁移（妙手提示：三级类目 L3 迁到七级 L7，升级后的店铺只能用 L7 发品） | 妙手授权页 | 类目映射必须带版本，见第 5 节 |

### 3.4 店铺授权

| 设计 | 来源 | 状态 |
|---|---|---|
| 店铺分组、别名、排序 | 妙手 | ❌ |
| 「店铺状态检测」+「需要更新授权的店铺」提醒 | 妙手 | 只有手动“检测连接” |
| 一个店铺只能授权给一个账号；多店铺授权互不关联 | 妙手 | ❌ 需要加唯一约束（跨 workspace） |
| 授权分类：店铺 / 货源账号 / 其他 | 妙手 | ❌ |

### 3.5 不跟的

- **同平台跟卖**（妙手「极速上品」：采 Ozon 发 Ozon、「店铺互采」）：平台严打，合规风险高，不做或放到最后。
- **满屏新手引导气泡**：妙手每页都弹，打断操作。我们用空状态 + 一次性清单来引导。
- **把 AI 做成单独的工具页 + 积分**：见第 1 节。

## 4. 交互原则（“现代化”的具体含义）

实测妙手的交互特征：顶部 11 个一级菜单 + 左侧两列密集入口；功能以“页面 / 工具”为单位切分；长表单；异步任务要去另一个“任务列表”页看结果。我们的原则：

1. **按流程组织，而不是按功能堆菜单。** 一级导航只保留：采集箱 → 刊登（草稿 / 在售 / 异常）→ 店铺 → 设置。其余能力都在流程节点里出现。
2. **不跳页。** 列表点一行 → 右侧抽屉编辑，编辑完回到原位；批量操作在当前列表完成。
3. **异步任务就地可见。** 发布 / 采集 / AI 处理的进度直接显示在对应行上（现在靠轮询，后续用 SSE），失败原因就地展开，可一键重试。统一的“任务中心”只用来查历史。
4. **AI 结果一律以“建议”呈现。** 并排 diff，可逐条接受；接受前不覆盖原数据；可回退。
5. **状态模型统一、可解释。** 每个商品任何时刻只有一个主状态 + 可选警告，警告一律说明原因和处理方法（目前已有：发布失败 / 已发布但有警告 / 店铺侧已删除）。
6. **键盘优先 + 命令面板。**（妙手也有“快速搜索功能”，说明用户确实需要。）
7. **插件与工作台一体。** 插件面板显示团队 / 授权状态，工作台能直接驱动插件采集（已实现：贴链接采集）。

## 5. Shopify 没有强制类目，类目怎么做

- Shopify **不强制**，但有 [Standard Product Taxonomy](https://shopify.github.io/product-taxonomy/)（`product.category`，值为 `gid://shopify/TaxonomyCategory/...`）。设置后：自动算税、同步到 Google / Meta 等渠道更准、可以使用该类目的标准属性（颜色 / 尺码 / 材质等 category metafields）。不设置时 Shopify 后台会自动建议一个。
- 其他平台（Shopee / TikTok / Amazon / Ozon / Temu）**强制叶子类目 + 必填属性**，这是跨平台最重的数据工作。

**做法（先在 Shopify 上把机制跑通，再复用到其他平台）：**

1. **来源类目**：采集时已拿到 1688 `leafCategoryId` / `leafCategoryName`（目前只存了名称到 `categoryPath`，需要把 ID 也存上）。
2. **平台类目树缓存**：`channel_categories(platform, version, id, path, attributes_schema)`。Shopify 用 Admin API `taxonomy { categories(search:) }` 按需搜索，不必全量；其他平台全量拉取、定期刷新。**必须带 version**（平台会迁移类目，见 3.3）。
3. **映射表**：`category_mappings(workspace_id, source_platform, source_category_id, channel, channel_category_id, version, confidence, confirmed_by)`。
   - 第一次遇到某个 1688 类目：AI 根据类目名 + 商品标题 + 属性推荐 Top-3 → 用户确认 → 记住。
   - 之后同一来源类目自动套用；置信度低的进入“待确认”。
4. **属性映射**：1688 `featureAttributes`（约 40 个）→ 平台必填属性，由 AI 做值归一（如 “304不锈钢” → Material: Stainless Steel）；缺失的必填项在编辑页标红。
5. Shopify 的 `productSet` 写入 `category` + 对应 metafields。

## 6. 路线图（按顺序；每个阶段带验收标准，方便分派给其他 AI）

### Phase 0 — 收尾与加固（1 周内）
- [ ] 部署：生产 Postgres（Neon / Supabase / RDS 任选）+ R2 + 公网 HTTPS 域名；插件用 `EXT_APP_ORIGINS` 构建生产版
- [ ] Shopify：`application_url`、`redirect_urls` 改成正式域名；注册 `app/uninstalled` 和合规 webhooks；公开应用 OAuth 路径联调
- [ ] CI：typecheck + test + 插件构建
- [ ] 采集箱 / 刊登列表：分页之外补充货源 ID、价格区间、店铺、状态筛选
- 验收：新用户在正式域名上完成 注册 → 装插件 → 采集 → 认领 → 发布 全流程

### Phase 1 — AI 产线 + 类目（核心差异点）
- [ ] `ai_jobs` 管线（复用 jobs 表）：认领时自动排队，可在店铺设置里关闭
  - 翻译（按店铺语言）、标题改写（长度 / 关键词 / 平台 SEO 规则）、描述生成（基于属性表，HTML）、**清理 1688 话术**（如“【定制联系客服】”“厂家直销”）、变体名与选项名翻译
  - 结果存为 `listing_suggestions`（字段级），编辑页并排 diff，逐条 / 批量接受
- [ ] 类目映射（第 5 节 1–5），先支持 Shopify
- [ ] 发布前检查：品牌词 / 敏感词 / 平台禁售词列表；图片侵权先接第三方服务，作为警告而不是阻断
- [ ] 采集设置（预处理规则）：标题前后缀、替换词、价格区间过滤、图片数量上限
- [ ] AI 用量计量（按 workspace，为计费做准备）
- 验收：采集一个 1688 商品并认领后，不手动改任何字段就能发出一个**英文、类目正确、无供应商话术**的 Shopify 商品；审核页能看到每个字段的 AI 修改并回退

### Phase 2 — 托管（在线商品 + 货源监控）
- [ ] 在线商品回拉：价格、库存、标题的店铺侧修改同步回来（现在只同步状态）；冲突时以哪边为准要有明确规则和提示
- [ ] 货源监控：定时（插件在用户浏览器内 / 服务端）重采 1688，价格 / 库存 / 下架变化 → 提示或按规则自动改价、自动下架
- [ ] Shopify webhooks（`products/update`、`products/delete`）替代轮询（需要公网地址）
- [ ] 图片 AI（白底图、图片翻译、去水印）——依赖已完成的图片存储
- 验收：1688 源商品涨价 10%，24 小时内我们提示或自动调价，Shopify 价格同步更新

### Phase 3 — 效率交互
- [ ] 任务中心（采集 / AI / 发布 / 同步的历史、失败原因、重试）
- [ ] 可保存的筛选视图、列配置、分组 / 标签 / 备注
- [ ] 批量编辑（改价两种模式、批量标签、批量 AI 重写）
- [ ] 右侧抽屉编辑、键盘快捷键、命令面板
- [ ] 「采集并自动认领 / 自动发布」（在 AI + 发布前检查稳定之后）
- [ ] 采集箱过期清理策略

### Phase 4 — 第二个渠道
- [ ] 选一个：**TikTok Shop**（风口）或 **Ozon**（开发者门槛低、用户最初就想要）。按 `ChannelAdapter` 实现：`verify / publish / fetchStatuses` + 新增 `prepareMedia`（平台图片 ID）+ 类目 / 属性 schema
- [ ] 编辑页由平台 schema 驱动（芒果的做法），Shopify 编辑页也迁到同一机制
- 验收：同一个采集条目认领到 Shopify + 第二平台，两边都能发出去，AI 产线与类目映射复用

### Phase 5 — SaaS 化
- [ ] 套餐与计费（Stripe / 国内支付二选一），套餐维度：店铺数、月采集数、AI 额度
- [ ] 团队成员邀请、角色权限（owner / admin / member）、“只看自己采的”（店小秘有此设置）
- [ ] 操作历史 / 审计
- [ ] 店铺唯一性（一个店铺只能授权给一个团队）、授权过期提醒
- [ ] 登录限流、邮箱验证、找回密码
